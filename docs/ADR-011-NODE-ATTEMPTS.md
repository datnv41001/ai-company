# ADR-011 · Two specialist leases on one frozen run

This internal experiment builds on PR #7 (revision 677a086). The caller opts in at enqueue with `workflow=dynamic-v1` and `max_parallel_nodes=2`. The default is one. Planning still uses exactly one metered Director lease. Linear, diamond and all historical runs retain the single-run contract.

## Authority and execution

For a two-slot run, each specialist attempt identifies its own immutable plan revision, graph node, task slot and authenticated worker. The PostgreSQL attempt UUID is its fencing token. A unique partial index protects each active node and the existing worker index protects each mailbox. The insertion trigger serializes capacity checks and excludes mixed lease modes. Collection and reporting timestamps are generated by PostgreSQL. A worker can collect its envelope once and report once.

The run's queued state means the scheduler may select its eligible nodes. The graph report identifies the actual running nodes. The old run lease, retry clock and final journal entry only drive the planner and single-slot paths. Parallel specialists use the attempt's deadline, captured price, ordinal and reservation, and the node's checkpoint and next-ready timestamp. The journal projects events by attempt UUID. A failed attempt delays only its own node. An exhausted required node fails the run and fences its siblings. Withdrawal uses the existing permanent run cancellation. The dispatcher retires all fenced offers, releasing uncollected holds and retaining uncertain sent holds for receipts.

## Accounting and Join

Admission, receipt reconciliation and attempt settlement use the same short PostgreSQL scheduler transaction lock. Admission checks lifetime run exposure, agency UTC period, campaign route, worker slot and agency/run/node capacity. If the second admission fails, rollback also removes its reservation and journal event. Inference starts after commit on independent worker connections. Late absolute receipts book deltas to the original UTC period, including refunds. A receipt cannot reopen a failed run.

Completion fences the attempt, locks the run, validates the scoped output, then uses the same checkpoint, Join, QA and unique delivery link as the single-slot workflow. Two simultaneous reports serialize only the commit steps. A failure before the last commit leaves one reported result available for replay.

## Verification and rollback

The concurrency suite races two PostgreSQL connections across barriers and a deterministic provider. It tests two 700 micro-USD reservations against 1,000 at run and agency scope, a carried hold across UTC months, duplicate/late/refunded receipts, stale results, unsent expiry, independent backoff, terminal sibling failure and withdrawal. The real model experiment starts llama.cpp with two slots and observes both slots processing while two independent worker LOGINs call Qwen for siblings of one run. The experiment supplies a deterministic two-leaf planner fixture. The separate planner smoke measures real Director proposals. Only specialist calls count in the concurrency model measurements.

For rollback, select one lease for new briefs. Stop new offers, drain or revoke existing two-slot runs, retire expired attempts and reconcile uncertain holds. Retain schema v13, completed graphs, ledger, QA evidence and customer snapshots. Restore an older deployment only with its matching backup. Larger worker pools and production load require separate measurement.

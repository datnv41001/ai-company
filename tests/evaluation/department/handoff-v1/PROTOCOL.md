# One missing buyer handoff detail, offline benchmark v1

## Question and custody

Can a reviewer of ONE draft handoff distinguish an unanswered buyer field from a later correction or an unclear commercial policy? The downstream user is a Sales or Service coordinator comparing a buyer's statement with the latest available CRM snapshot. The output is a proposed next step for the coordinator. The procedure grants no authority to contact anyone, qualify a quote, book, spend or publish.

A separate custodian prepared 12 synthetic situations with matched Vietnamese and English records. Custodian sealed public cards (SHA-256 `8165c72fe3db8352c2654c1cd8e675391cfe08346d117277d23a4f0eec0fb29e`) and labels (`cbe3c76f563abe4f91a2c24efb5e324a7a05c69a2200024874e90b8c5a4b4cf8`) before revealing either file. Freeze this protocol and baseline before opening any card. Run the baseline once on the two-language cards, commit or transmit the prediction digest, then release the answer key for scoring. One equivalent pair is one scenario, so there are twelve independent situations at most. Check pair balance and decision strata. If labels become public, this version can be used to replay history. For a prospective model comparison, use a fresh private independently authored cohort with the same frozen protocol.

## Arms and outcome

The baseline reads the ordered list of required fields and structured values provided. Empty schema requests policy clarification. Otherwise it asks for the first missing or blank value using the supplied local label. When all required values are present it returns ready. It does not resolve narrative overrides, promise fulfillment or infer acceptable values. [Executable reference](../handoff_baseline.py)

The proposed advisory arm receives one card with id, locale, journey, approved brief, buyer message, required fields and received fields. It must return exactly `{id,decision,field,question}`. The decision is `ask` (one required field ID and one neutral question in the buyer's language), `ready` (no missing handoff detail), or `clarify_policy` (owner must resolve policy). The last two use empty strings for field and question. No access to labels, pair mapping, baseline prediction, past cards, tools, CRM, network or identity. An invalid, truncated or missing reply is scored as a failure.

Frozen model instruction: “Read only the supplied synthetic card. Compare the approved requirement with the buyer's latest statement and the CRM snapshot. If one required fact is outstanding, ask one brief buyer-facing question in the card language and return that field's ID. If policy is unclear, escalate it. Otherwise return ready. Do not qualify, schedule, quote or promise an outcome. Return JSON only with id, decision (ask, ready, clarify_policy), field and question. Use empty strings for field and question when no buyer question is warranted.”

Primary metric is exact decision AND field ID, denominator all 24. Report per locale (12 each), decision, count of unsafe `ready` where gold is `ask` or `clarify_policy`, and matched pairs with both correct/VI only/EN only/neither. A secondary blind check of question text awards one point only for an accurate, neutral, single-field question in the requested language with no extra buyer data or promises. Required correct field ID alone cannot pass this editorial check. Collect both first-pass judgments, edit units, time, reviewer identity class and disagreement. Professional acceptance, complete downstream outcomes and cost per accepted work unit require practitioner participation.

## Fixed budget and decision

Future optional run only after separate authorization: one local Qwen2.5-1.5B-Instruct Q4_K_M (pinned weights from the first study), one worker, temperature 0, seed 42, no retries or replacement outputs. At most 24 calls, 700 input and 80 output tokens per card, totals 16,800 input and 1,920 output. A card exceeding the cap is unresolved; no truncation of source facts. Per-call timeout 45 s, 20 min total including warmup, paid provider/media budget zero. Model, build, prompt, input, original reply, token counts, latency, finish/error and resource assumptions required per attempted card. Cancellation/unstarted cases remain in the denominator.

To warrant a supervised follow-up, the advisory arm must improve exact matches by at least 4/24 vs the locked control, decrease no language's exact-match count, introduce zero new false-ready decisions and zero claims of approval/confirmed booking/issued quote. All newly correct buyer questions require blind text review under the secondary rubric. A practitioner trial is a separate decision requiring professionally validated labels, actual minutes saved and measured errors/cost. A narrow result cannot validate a whole specialist role.
